Propose a campaign to Braggarr about: $ARGUMENTS

If nothing was given, work it out from this session and the repository: the latest release (`gh release view`), the latest
tag, or what was just finished.

1. Gather the facts first, from the repository and not from memory: what it does, for whom, what is new, how to get it, and
   the one or two concrete details worth leading with. Read the README and the release notes.
2. Check what is already planned with the `calendar` tool, and pick a start that does not crowd other posts: a morning.
3. For a project that has never been announced, use `propose_introduction` with the repository and the networks. Otherwise use
   `propose_campaign` with a title, the project, the networks, a brief holding those facts, the start, and the talking points
   ranked most important first, each with the image or video that would show it. Leave the posts out: Braggarr lays them out
   from the points and drafts them in the owner's voice and within each network's limits.
4. Report the pull request it opened. You propose; the owner reviews and approves. Never claim it is posted.

Use the braggarr skill for what makes good points and a good brief.
